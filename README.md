# Twinslop

Две вещи в одном репозитории:

1. **Twinslop Hands** — телефонный контроллер «два стика = две руки». Открывается
   в браузере телефона, работает как приложение (PWA), отдаёт положение рук по HTTP.
2. **`apk-report/`** — разбор APK из релиза `Ai` (`WVRClientv1release.1.apk`):
   что это за приложение, как устроен стрим, что за модификация внутри.
   Главный документ — [`apk-report/DEEP-REVIEW.md`](apk-report/DEEP-REVIEW.md).

## Twinslop Hands: два стика под телефон

### Запуск

```bash
node server.js          # без зависимостей, нужен Node 18+
```

Сервер напечатает адреса. Открой на телефоне `http://<ip-компьютера>:3000`
(телефон и компьютер — в одной Wi-Fi сети), поверни экран горизонтально.

- **Левый стик = левая рука**, **правый = правая**. `TRIG` и `GRIP` — кнопки
  указательного и среднего пальца для каждой руки.
- Значения `x, y` — от `-1` до `1`, где `y = 1` — вверх.
- В центре экрана — виртуальная плоскость с руками, видно, что уходит наружу.
- ⚙ — чувствительность, мёртвая зона, вибрация, инверсия по вертикали.
- ⛶ — полный экран + попытка зафиксировать ландшафт (Android/Chrome).

### APK (без интернета вообще)

Готовый APK лежит в релизе: **[Twinslop Hands APK](https://github.com/Belopus228/Twinslop/releases/tag/hands)**
(`TwinslopHands.apk`, ~0.4 МБ). Скачивается и ставится прямо с телефона
(Android разрешит «Установить из неизвестных источников»).

Внутри — тот же контроллер, но:

- веб-часть зашита в `assets/www`, приложение работает **полностью офлайн**;
- в `AndroidManifest.xml` **нет разрешения `INTERNET`** — то есть сетевых
  проверок и запросов в принципе быть не может, система их заблокирует;
- ландшафт зафиксирован, экран не гаснет, системные панели скрыты (immersive).

Собрать заново: `gh workflow run android-apk --ref arena/ac9c8af6-twinslop`
или локально `cd android && gradle assembleRelease` (нужны JDK 17 и Android SDK).

В браузере тот же интерфейс работает как PWA: добавь на домашний экран
(Chrome → «Установить приложение») — откроется без адресной строки.

### Что уходит на сервер

`POST /api/state` каждые 33 мс:

```json
{
  "L": { "x": 0.42, "y": -0.13, "trigger": 1, "grip": 0 },
  "R": { "x": -0.80, "y": 0.55, "trigger": 0, "grip": 1 },
  "sensitivity": 1.3,
  "deadzone": 0.06
}
```

Забрать оттуда:

| Метод | Что даёт |
|---|---|
| `GET /api/state` | последнее состояние + `age_ms` (сколько мс назад обновлялось) |
| `GET /api/stream` | SSE-поток изменений, подходит для реального времени |

```bash
node examples/read-hands.js http://localhost:3000   # печатает руки в консоль
```

Клавиатура для проверки без телефона: `WASD` — левая рука, стрелки — правая,
`Space` — хват, `Shift` — курок.

## SLOP APE — своя игра с двумя стиками

Оригинальный прототип «паркур руками»: вся геометрия процедурная, ассеты свои,
никаких файлов GILLA внутри. Три файла, ноль серверов.

**Управление:** палец на стике = рука цепляется за поверхность и подтягивает
тело. Отпустил — полетел по инерции. Двумя руками по очереди забираешься по
спирали из 24 платформ к камню наверху.

```bash
node server.js            # затем открой /game.html
npm run build:game        # пересобрать bundle после правок src/game/main.js
node test/smoke.mjs       # headless-тесты физики (без браузера)
```

В APK игра уже внутри: в контроллере кнопка **▶** в правом верхнем углу.

### Эмулятор шлема (VR-режим)

Кнопка **VR** в игре превращает телефон в подобие шлема:

- **стерео-рендер** — два вида, камеры разнесены по IPD (слайдер 54–74 мм);
- **трекинг головы** — гироскоп устройства, а если браузер датчики не даёт,
  работает свайп по экрану;
- **профили устройств** — Quest 3S (2064×2208 на глаз, 90 Гц), Quest 3 (120 Гц),
  Cardboard (960×1080, 60 Гц) — с честным счётчиком FPS и проверкой,
  дотягиваем ли до целевого рефреша;
- виньетка и разделитель для комфорта, разделитель скрывается в плоском режиме.

Границы, чтобы не было сюрпризов: это эмулятор **шлема** — дисплея, оптики
и трекинга. Аккаунт Meta, энтайтлменты и сервисы Horizon он не подделывает,
поэтому APK из магазина внутрь не запускаются. Свой контент (игра, WebXR-сцена,
тестовый рендер) — работает полностью офлайн.

Технически: three.js (собран в один файл, работает офлайн), физика на руках —
пружинная тяга к точке захвата + гравитация, столкновения с AABB, камера
следит за направлением движения. Тесты в `test/smoke.mjs` прогоняют физику
в Node с заглушённым рендером: проверяют, что тело стоит на платформе, рука
цепляется, тело подтягивается, скорость не улетает в космос и респавн работает.

## Настройки (⚙)

Отдельная страница `settings.html`, одна на всё приложение:

- **какой стик за какую руку** — переключатель «поменять руки»; работает и в
  контроллере (буквы на стиках меняются), и в APE HEIST;
- чувствительность 0.4–2.6×, мёртвая зона 0–0.4;
- инверсия вертикали, вибрация, «не гасить экран»;
- сброс к значениям по умолчанию;
- инструменты (разбор APK, список приложений) переехали сюда с главного экрана.

Хранится в `localStorage` под ключом `twinslop-hands`; страницы перечитывают
настройки при возврате (`pageshow` / `visibilitychange`), поэтому менять их
можно на ходу. Валидация и карта «стик → рука» — в `src/shared/settings.js`,
покрыты `test/settings.mjs`.

## Реверс APK: инструкция и триаж

- **`docs/REVERSE-APK.md`** — пошаговый разбор APK: окружение, триаж, манифест,
  dex → Java, ELF, определение движка, Unity/IL2CPP, детект защиты, Ghidra,
  динамика на своём стенде, шаблон отчёта и таблица типичных ошибок.
- **`scripts/apk-triage.sh <app.apk>`** — автоматизирует триаж: хэш, состав, dex,
  ABI, нативные библиотеки с секциями, маркеры движка, магия и карта энтропии
  `global-metadata.dat`, вердикт «защищено / читается статически».
  Ничего не расшифровывает — только описывает файл.

```bash
./scripts/apk-triage.sh sample.apk out/
```

Читать инструкцию:

- **в приложении**: Настройки → Инструменты → «Инструкция по реверсу APK» (офлайн);
- **в браузере**: `docs/REVERSE-APK.html` — автономный файл, печатается в PDF
  через «Печать → Сохранить как PDF»;
- **пересобрать HTML** после правок `.md`:
  `pip install markdown && python3 scripts/md2html.py docs/REVERSE-APK.md docs/REVERSE-APK.html`

## APE HEIST — своя игра в жанре «обезьяна на руках»

Кнопка **🐒** (страница `ape.html`). Жанр тот же, что у Gilla, но **ни одного
ассета, строки кода или названия оттуда** — только механика, а механики
копирайтом не защищены. Всё нарисовано примитивами three.js, звука нет,
сети нет.

Правила:

- **два стика = две руки**; кисть — это маленькая сфера: она **упирается в ящики,
  пол и стены** и не проходит сквозь них (радиус 0.11);
- цепляться можно **за любую поверхность**, а не только за углы: захват идёт по
  точке контакта, рука прижимается к грани и подтягивает тело;
- двигаешься быстро или падаешь — **шумишь**, монстр слышит (полоса «ШУМ»);
- стоишь тихо — он тебя теряет и уходит обходить;
- режим **«Ограбление»**: собери 3 единицы добычи (золото и алмазы) и уйди в
  зелёный круг, пока не поймали;
- режим **«Продержись»**: 90 секунд в комнате с монстром;
- камера — свайп; на клавиатуре WASD — левая рука, стрелки — правая.

Что внутри:

| Файл | Роль |
|---|---|
| `src/ape/sim.js` | вся симуляция: физика рук, гравитация, коллизии AABB, шум, ИИ монстра, добыча, условия победы. Без three.js — тестируется в Node |
| `src/ape/main.js` | рендер three.js, камера, стики, HUD |
| `test/ape.mjs` | 39 headless-проверок: хватка, подтягивание, отпускание, шум, реакция монстра, поимка, выход, таймер, детерминированность уровня |

Монстр — конечный автомат `patrol → alert → chase → patrol`; слышит в радиусе
`4.2 + 8.4 × шум`, теряет через 2.4 с тишины. Уровень детерминирован по seed.

## Приложения на телефоне

Кнопка **📱** открывает список установленных приложений (читает `PackageManager`
через JS-мостик): поиск, системные в конце, бейдж `VR` у приложений с
OpenXR-разрешениями. Выбираешь приложение — приложение честно говорит, что будет:

| Действие | Возможно? |
|---|---|
| Показать список установленных приложений | да (`QUERY_ALL_PACKAGES`) |
| Прочитать его разрешения и `targetSdk` | да, это публичный манифест |
| Запустить его | да, обычный `startActivity` |
| Показать свои стики поверх него | да, но как оверлей — ввод в чужое приложение не проходит |
| Подменить его рендер, влезть в память | **нет** — песочница UID/SELinux, `ptrace` запрещён, нужен root |
| «Эмулировать VR» для Quest-приложения | **нет** — ему нужен OpenXR-рантайм и сервисы Meta |

Поэтому «прицепиться и запустить с эмуляцией» в формулировке «подменить чужой
процесс» невозможно ни у нас, ни у кого-либо без root. Что реально работает —
запуск, оверлей и предупреждение вида «это VR-приложение, на телефоне не пойдёт».

## Разбор APK внутри приложения

Кнопка **📦** в контроллере открывает экран разбора: выбираешь любой `.apk` —
приложение читает его прямо на телефоне (никакой сети, разбор локальный) и
показывает пакет, разрешения, архитектуры, движок, наличие OpenXR/Meta SDK,
состояние метаданных IL2CPP и список крупнейших файлов.

Дальше — честный вердикт, один из трёх:

| Вердикт | Когда | Что значит |
|---|---|---|
| Это наше приложение | пакет `ai.arena.twinslop` | ставится системой, грузить внутрь не нужно |
| VR-приложение (Quest/OpenXR) | есть OpenXR-загрузчик или Meta SDK | нужен рантайм шлема и сервисы Meta |
| Обычное Android-приложение | всё остальное | Android не даёт одному приложению исполнять код другого |

Кнопка **Релиз** открывает страницу с нашим APK во внешнем браузере — самому
приложению сеть для этого не нужна, ссылку открывает система.

Честно про рамки: «загрузить и запустить чужой APK» одним приложением нельзя —
это уровень ОС. Чтобы исполнять APK, нужна виртуализация (как VMOS) или
установка в систему. Поэтому экран и называется «разбор», а не «запуск».

## Разбор APK

```
apk-report/
  DEEP-REVIEW.md    — главный отчёт: что за приложение, стек, стрим, модификация, риски
  SUMMARY.md        — паспорт: пакет, разрешения, движок, крупнейшие файлы
  deep/
    scripts.txt     — 3264 имени MonoScript (карта игровых систем)
    libs/           — строки нативных библиотек (стрим, микрофон, модкит)
    decrypt/        — крипто-проба: шифрование метаданных, упаковка модкита
```

Отчёт пересобирается автоматически — workflow `apk-inspect` скачивает APK,
разбирает его и коммитит результат:

```bash
gh workflow run apk-inspect --ref arena/ac9c8af6-twinslop
```
